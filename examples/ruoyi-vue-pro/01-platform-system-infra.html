3. 系统设计

运行时（默认 local）：浏览器 → 管理端静态资源（独立仓库构建）→ HTTP /admin-api/** → yudao-server（端口配置 48080）→ MySQL 主从配置（slave 可懒加载）→ Redis。 对象存储走文件配置表指向的客户端（本地/S3/FTP 等）。定时任务 Quartz JDBC，local 曾排除自动配置，需对照 yaml。 消息队列支持 Event/Redis/Rabbit/Kafka/Rocket，属可选项。

模块边界：system 拥有身份、权限、租户、通知渠道；infra 拥有文件、代码生成、任务、动态配置、API 日志；framework 提供 Web 前缀、Security、租户插件、数据权限、MyBatis。

认证与授权

  • 过滤器链：CORS 开、CSRF 关、STATELESS、TokenAuthenticationFilter 在 UsernamePassword 之前。
  • 令牌头名默认 Authorization。admin-api 与 app-api 的 userType 必须与令牌一致。
  • 权限：@EnableMethodSecurity + @ss.hasPermission，权限字来自菜单 type=3。

登录时序

  1. 浏览器打开管理端登录页（组件在独立前端仓库，路由由后端 GET /admin-api/system/auth/get-permission-info 在登录后下发菜单）。
  2. 若 yudao.captcha.enable=true，先走 AJ-Captcha 滑块；local 配置将其设为 false。
  3. POST /admin-api/system/auth/login，请求体 AuthLoginReqVO：username 4–30 位字母数字、password 4–16 位，可附带社交绑定字段。
  4. AuthController.login → AdminAuthServiceImpl.login：校验验证码，authenticate 按用户名查 system_users，PasswordEncoder（BCrypt）比对，禁用则失败。
  5. 失败写入 system_login_log 并抛出业务错误码；成功则 OAuth2TokenService.createAccessToken 写入 system_oauth2_access_token / refresh token，更新最后登录时间。
  6. 响应 CommonResult，code=0 表示成功，data 为访问令牌。
  7. 后续请求在 Header Authorization 带 token。TokenAuthenticationFilter 调 OAuth2TokenCommonApi.checkAccessToken 填充 LoginUser（含 tenantId）。
  8. 方法级 @PreAuthorize("@ss.hasPermission('...')") 对照角色-菜单权限字。数据权限由 @DataPermission 与 MyBatis 拦截器追加部门条件。
  9. 租户：继承 TenantBaseDO 的表由 TenantLineInnerInterceptor 自动加 tenant_id 条件，不是数据库外键。

可见失败态：验证码错误、账号密码错误（同一文案）、用户禁用、令牌无效走认证入口、无权限走 AccessDenied。CSRF 在 Security 配置中关闭（无 Session，走 token）。

新增用户时序

  1. 已登录管理员打开菜单「用户管理」，组件名 system/user/index，完整路径由菜单树拼接为 /system/user。
  2. 列表：GET /admin-api/system/user/page，权限 system:user:query。
  3. 新增：POST /admin-api/system/user/create，权限 system:user:create，请求 UserSaveReqVO。
  4. UserController.createUser → AdminUserServiceImpl.createUser：按租户 accountCount 限制人数；校验用户名/手机/邮箱唯一与部门、岗位存在；BCrypt 加密密码；插入 system_users；岗位写入桥表 system_user_post。
  5. 成功返回新用户 id；校验失败抛 ServiceException，由全局异常封装为 CommonResult 非 0 code。
  6. 删除为逻辑删除（MyBatis-Plus deleted 0/1），不是物理 DROP。

禁用业务模块时，DefaultController 对 /admin-api/bpm/** 等返回未实现错误，避免前端打到空 404。member 路径未做同样占位。

6. 接口与类设计

约定：管理端前缀 /admin-api 匹配 **.controller.admin.**，App 前缀 /app-api。 成功包络 CommonResult.code = 0，msg 可空，data 为负载。时间戳 Jackson 配置为毫秒。分页使用 PageParam/PageResult。 内容类型为 JSON。幂等与限流由 protection starter 提供注解，登录短信接口处有限流注释但默认未打开。

本分册 HTTP 操作 347 个（system 212、infra 116、server 19）。

登录接口

POST /admin-api/system/auth/login
  • 目的：账号密码登录。
  • Header：无令牌。Body：username、password，可选 captchaVerification、social*。
  • 校验：@Valid + @NotEmpty + 长度/正则；验证码取决于配置。
  • 成功：code=0，data 含 accessToken、refreshToken、userId、expires。
  • 失败：验证码错误、坏凭证、禁用用户。事务：登录日志插入与令牌创建在服务方法中完成；login 本身未标 @Transactional。
POST /admin-api/system/user/create
  • 权限 system:user:create。Body UserSaveReqVO。成功返回用户 id。副作用：写用户与用户岗位，写操作日志上下文。

7. 开发、测试、部署与运维

本地链（源码）

  1. JDK 8（master）或文档所述的 jdk17/jdk25 分支；本分析未切换分支。
  2. 导入 sql/mysql/ruoyi-vue-pro.sql 与 quartz.sql 到配置的 schema（local 示例库名 ruoyi-vue-pro-jdk8）。
  3. 启动 Redis、MySQL。后端 yudao-server，profile 默认 local，端口 48080。
  4. 前端需单独克隆 yudao-ui-admin-vue3，不在本仓库完整提供。
  5. 无 Flyway；schema 以 SQL 脚本为准。

本分析执行的检查

  • 已做：git fetch 对比、SQL/Java/菜单静态盘点、文档站与 Vue3 演示首页只读 GET。
  • 未做：mvn test / mvn package（JDK 21 与工程声明 JDK 8 不一致，结果不能代表项目 CI）。
  • 仓库内测试类：system 39、infra 26、framework 25。模块测试资源为 H2 create_tables.sql。

部署

yudao-server/Dockerfile：eclipse-temurin:8-jre，拷贝 yudao-server.jar，暴露 48080。 script/docker/docker-compose.yml 含 mysql8、redis6、server、admin；MySQL 初始化挂载主 SQL；admin 构建上下文 ./yudao-ui-admin 与当前仓库目录并不一一对应，按该 compose 启动前需自行对齐前端构建目录。

script/shell/deploy.sh：备份 jar、SIGTERM 等待最多 120 秒、健康检查 URL http://127.0.0.1:48080/actuator/health/。SkyWalking 环境变量默认注释。

已知边界

  • 主 SQL 日期早于 HEAD，菜单可能含默认未启用模块的入口。
  • CRM/ERP 等无主 SQL 表，不能从本脚本得到其物理库。
  • 演示 API 根地址当前 404，线上行为未验证。
